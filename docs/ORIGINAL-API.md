# API оригинального Windows EXE

Карта относится к `PostgreSQL_JOIN90_Windows_x64/PostgreSQL_JOIN90.exe`,
не к переписанному серверу. Маршруты сверены с
[декомпиляцией](../reverse-engineering/original-windows/pseudocode/main.c)
и вызовами интерфейса в [app.js](../web/app.js).

## HTTP-доступ

- `Host` должен соответствовать адресу сервера; переданный `Origin` тоже
  сверяется с ним.
- Для `/api/*` нужен `X-Trainer-Token`. `/health` доступен без токена и его не
  возвращает.
- Статика обслуживается через `GET`/`HEAD`. В таблице ниже указаны методы,
  которыми пользуется штатный интерфейс; это не утверждение о полной
  allowlist методов серверного диспетчера.

## Маршруты

| Метод | Путь | Действие интерфейса | Результат |
|---|---|---|---|
| `GET` | `/health` | — | Состояние приложения, курса и версии; без токена |
| `GET` | `/api/catalog` | Старт страницы | Задания, теория и данные курса |
| `GET` | `/api/compiler` | Старт; «Настройки» | Состояние и конфигурация среды |
| `POST` | `/api/compiler` | «Сохранить настройки» | Сохраняет конфигурацию среды |
| `POST` | `/api/compiler/probe` | «Пробный запуск» | Запускает тестовый запрос |
| `POST` | `/api/workspace/load` | «Открыть» | Загружает работу по имени |
| `POST` | `/api/workspace/save` | Автосохранение, Ctrl+S | Сохраняет код и ответы |
| `POST` | `/api/run` | «Запустить», «Запустить пример» | Исполняет SQL и возвращает вывод |
| `POST` | `/api/check` | «Проверить задание», «Проверить все карточки» | Проверяет задание и сохраняет результат |
| `POST` | `/api/analysis` | «Сохранить ответы на разбор» | Передаёт письменные ответы на ручную проверку |
| `POST` | `/api/cancel` | «Остановить» | Отменяет текущий запуск |
| `GET` | `/api/export?student=…` | «Сдать работу .zip» | Возвращает ZIP работы |
| `POST` | `/api/open-folder` | Настройки → «Открыть мою папку» | Открывает папку работы в Windows Explorer |
| `POST` | `/api/shutdown` | «Завершить работу» → подтверждение | Останавливает сервер |

`/api/run` принимает код и stdin. `/api/check` принимает работу и задание;
статус проверки (`passed`/`failed`) — это результат задания, не HTTP-ошибка.

## Проверено в запуске

Оригинал запущен через Wine в отдельном network namespace с loopback-only
доступом; UI открыт в Chromium. Все UI-маршруты выше вернули `200` при
валидном запросе. Проверены загрузка и автосохранение работы, запуск
`SELECT 1`, проверка задания, письменный разбор, пробный запуск PGlite,
экспорт ZIP, остановка выполнения, открытие папки и штатное завершение.

Письменный разбор без ответов вернул `400`; с заполненными полями — `200` и
статус «На разборе». `/api/check` вернул `200` с результатом `failed` для
намеренно неподходящего SQL. `/health` без токена и блокировка неверных
`Host`, токена и `Origin` также проверены. Экспорт — корректный ZIP.

Использован тестовый профиль и временный каталог данных; после проверки
сервер и временные файлы удалены. SHA-256 EXE:
`e45c4379c4d58bfdb94256bb7f4c41f579ebae2c7704e0dd522a1c5a0c45d909`.
